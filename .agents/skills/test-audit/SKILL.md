# Test Audit

Three modes share one value bar: **authoring** gates new or changed tests;
**audit** removes low-value coverage in a focused batch; **campaign** examines
one subsystem's whole test surface. Before a campaign, read
[CAMPAIGN.md](CAMPAIGN.md). Optimize for confidence and maintenance cost, not
deletion count.

Read [AGENTS.md](../../../AGENTS.md), [CONTRIBUTING.md](../../../CONTRIBUTING.md),
and applicable scoped agent instructions first. Their real-path testing standard
is mandatory: every user-visible behavior retains a test through `runner.run`
or the CLI, using real temporary Git worktrees, filesystem, and event loop,
with only external network/API boundaries stubbed. Assert observable outcomes;
unit tests supplement this proof. A smaller helper test cannot replace it.
For terminal findings, inject faults at actual filesystem read/write/install
operations as required by CONTRIBUTING.md; preserve the real path around the
fault rather than replacing the publication pipeline with a mock.

## Authoring gate

Before adding or changing a test, answer:

1. What observable behavior, invariant, or independent contract does it protect?
2. What credible regression makes it fail?
3. Why does existing coverage miss that regression? Name the primary owner test
   at the strongest boundary. Another layer needs a distinct risk, such as
   transport decoding, cancellation, or persistence failure. Prefer extending
   `pytest.mark.parametrize` or an existing fixture over duplicating setup.
4. Does it require a production export, flag, wrapper, or injection hook solely
   to expose implementation? Test the real boundary instead. Preserve legitimate
   `Backend` / `create_backend`, extension, and external-process boundaries.

A missing answer means the test is not ready. Check the patterns below; a match
requires the retention bar to identify its independent contract. Tests of
implementation must be rewritten at the owning boundary. An identifier-only
refactor should preserve a contract test; a change to shipped bytes may not.

Bug regressions must fail on the pre-fix code for the intended reason and pass
after the owner repair. Prove this with the same harness and inputs; a mock that
supplies the corrected result proves nothing about the fix. Avoid replaying the
same regression at every layer it crosses.

## Low-value patterns

Use this checklist for authoring and discovery:

- assertion-free coverage probes, self-comparisons, and identity copiers;
- copied inventories, fixtures, manifests, or export lists without a separate
  shipped contract;
- exact source/import/string greps tied to internal organization;
- private predicates or `assert_called*` checks duplicated by real outcomes;
- duplicate scenarios or backend-local replays of shared logic;
- test-only exports, reset globals, wrappers, and dead paths kept alive by tests;
- expected values generated by the helper or renderer under test;
- mocks that implement the asserted behavior, or an identical fake that erases
  meaningful differences between Claude, Codex, Pi, and Osprey;
- fixtures that prewrite artifacts, verdicts, or lifecycle events the production
  path should produce, or assertions against a store that path never writes;
- capability/config tests that restate flags without exercising their promises;
- negative controls that pass at the wrong guard or never reach the rejection;
- names that promise a stronger outcome than the assertions actually establish.

## Retention bar

Keep independent proof of CLI/config/defaults, extension APIs, backend event
streams, ATIF/trajectory emission, archive and corpus storage, security and
redaction, workspace confinement, cancellation/process cleanup, artifact
ownership, and release/package/workflow contracts. Preserve typed review
coverage, snapshot binding, and atomic publication from the
[terminal findings contract](../../../README.md#terminal-review-findings-contract).

Static, slow, or mock-backed is not by itself a deletion reason. In particular:

- retain ordering when it affects delivered events, frozen evidence, or cleanup;
- retain source/byte inspection when shipped prompts, packaged templates,
  schemas, or sandbox asset parity are the independent contract;
- retain distinct backend transport/replay cases even when shared event-handling
  coverage exists;
- retain real temporary SQLite/filesystem and fault-path tests where mocked
  state cannot prove persistence, atomicity, or recovery;
- reproduce baseline failures and distinguish environment, test, and product
  defects. Repair the owner when warranted; never delete a failure to turn green.

Read the complete test, parametrized rows, fixture chain, production owner,
entrypoint, callers, sibling implementations, overlapping tests, CI routing,
and relevant history before judging a candidate. Inspect dependency source or
types when a claim depends on SDK behavior. `daydream/atif/` is vendored with a
mechanical-update-only policy; pruning is not permission to hand-edit it.

## Discovery and evidence

Keep discovery read-only and report evidence before editing. Broad discovery
can fan out into production-owner lanes: runner/CLI/deep flows; backends and
Git/GitHub transport; artifacts/trajectory/archive/corpus; improve/extensions;
benchmark/tooling/workflows; and the separately locked RL project if in scope.
Assign each agent explicit paths and keep shared harness ownership with one
coordinator. Outside campaigns, prefer a few proven candidates.

Record all fields before deleting or consolidating a candidate:

- exact pytest node or declaration and affected parameter rows;
- the failure it actually detects;
- production callers, extension obligations, and remaining test consumers of
  the covered seam;
- stronger remaining test node(s), with matching inputs and failure modes, or
  evidence that no contract needs proof;
- relevant history and why the test or seam exists;
- production/test-support deletion unlocked;
- risk and the focused validation command.

For example, deleting a helper-call assertion about declining fixes requires a
keeper that enters the real runner, declines the gate, and observes unchanged
Git/files plus correct recorded state. A test that mocks the entire fix gate
cannot be that keeper. The real-path exemplars are in
`tests/deep_orchestrator/test_fix_gate_cleanup_and_precision.py`.

## Edit shape

Choose one coherent owner-boundary batch. Carry unique assertions into keepers
before deleting their old home. Remove obsolete test-only seams and dead paths
only after checking all consumers and public/extension contracts; retain useful
external-boundary and fault-injection seams. Prefer simpler production code,
without replacing deleted tests with new implementation assertions.

Reuse `tests/conftest.py` and `tests/harness/` for backend scripts, fake `gh`,
real Git, isolated artifact/archive roots, clocks, and fault injection. Preserve
their teardown, ContextVar, environment, and credential isolation. Vulture scans
production and tests together, so test references can hide dead production code;
explicitly inspect non-test callers before trusting a clean scan.

## Validation

Read the current [Makefile](../../../Makefile),
[pytest configuration](../../../pyproject.toml), and
[CI jobs](../../../.github/workflows/ci.yml). Never edit a checkout while its
tests are running. Use isolated checkouts for pre-fix controls or mutations,
preserving existing user changes.

1. Check the relevant lockfile with `uv lock --check` before `uv run` or syncing
   dependencies, so those commands cannot silently heal lock drift.
2. Run owner, sibling, and shared-harness consumers with
   `uv run pytest <node-or-path>`. Targeted runs have no coverage floor; they are
   focused proof, not the full gate.
3. Exercise the executable/dry-run or packaged artifact contract when replacing
   source assertions. Use `make actionlint` for changed workflow contracts;
   report its Docker-unavailable skip as a skip.
4. Run appropriate lint/type/dead-code checks, then `git diff --check`. Finish
   implementation audits with `make check`, including the integrated branch
   coverage gate. Preserve coverage settings and exclusions; follow
   [coverage policy](../../../docs/coverage.md) rather than adjusting gates to
   make pruning pass.
5. For `rl/daydream_review/`, run targeted pytest from that directory and
   `make rl-check` from the root. Root pytest does not collect RL; `make check`
   includes its dead-code scan but does not run its test suite.
6. Obtain a final independent read-only review of the audit changes against the
   pinned baseline, comparing deleted coverage with named keepers. Campaigns
   require the full preservation review in [CAMPAIGN.md](CAMPAIGN.md).
7. Inspect `git diff --numstat`; count production/tooling, tests, and support
   separately. If runtime reduction is claimed, compare identical selections,
   workers, coverage settings, and environments, including fixture setup cost.

Live CLI/GitHub and Docker-dependent proof has separate prerequisites. Inspect
the relevant markers and harness; record skipped/unavailable proof explicitly.
A narrow green run, coverage percentage, or live smoke test cannot establish
every retained contract.

## Landing and handoff

Commit, push, open a PR, or merge only within the user's authorization. Follow
Daydream's explicit staging, Conventional Commit, and signed-commit conventions.
Never bypass Git hooks by flags, environment variables, configuration, or other
mechanisms. Fix hook failures on the current branch and retry normally, or
report the blocker; landing is complete only when the ordinary command succeeds.

Report removed categories, owner simplifications, retained false positives,
keepers and preserved contracts, commands/results actually run, skips and
blockers, production versus test/support LOC, measured runtime if requested,
and PR/merge state. Name remaining work without claiming a partial audit is
complete. Refresh discovery against the current base before a subsequent batch.
